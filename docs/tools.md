# Клиенты данных помощника (FIN-220)

Адаптеры подключены в wire() к AskQuestion/RetryAnswer и циклу модели.
Принятие, бюджеты и оставшиеся части FIN-220 описаны в [generation.md](generation.md).

| Адаптер | RPC | Идентичность и чтение |
|---|---|---|
| AssistantConsent.Granted | user.GetAssistantConsentStatus | Явный проверенный user_id; метод user читает primary, результат не кешируется |
| FinancialData.Overview | statementdata.GetDataOverview | Явный user_id из Subject; чтение данных без принудительного primary |
| FinancialData.Aggregate | statementdata.AggregateOperations | То же; режим переводов берётся из серверного Subject |
| FinancialData.Find | statementdata.FindOperations | То же; ограниченный список и общее число совпадений сохраняются |
| FinancialData.Analytics | analytics.GetAnalytics | То же; актуальные blocks и метаданные, без устаревших полей 5–9 |
| FinancialData.Periods | analytics.ListPeriods | Явный user_id; периоды и их покрытие сохраняются |

Клиенты создаются поверх client.Dial: в сеть уходят собственный сервисный токен и
request ID, пользовательский токен, клиентские подсказки и входящий x-read-primary
не передаются. Повторы разрешены только для перечисленных читающих методов и только
при UNAVAILABLE. Срок отдельного вызова ограничивается внутри общего контекста;
более ранняя отмена или deadline вызывающего сохраняются.

Согласие действует только при granted и совпавших непустых version/current_version.
Отказ или устаревший документ дают false; неполный ответ, отсутствие соседа или его
ошибка не разрешают передачу данных. Технический текст соседа не возвращается.

Порт internal/tooldata не зависит от protobuf и gRPC. Аргументы типизированы;
user_id и режим переводов приходят отдельно от аргументов модели. Сервер проверяет
перечисления, диапазоны, совместимость all_time с датами и лимиты строк. Декодирование
JSON аргументов и JSON Schema реализованы в internal/generation: весь батч проверяется
до первого RPC, неизвестные поля и подмена серверного Subject отвергаются.

Результат несёт ограниченный JSON и отдельно доверенные Evidence: NO_DATA,
пути заблокированных блоков/плиток, признак усечения соседом и метаданные источника.
Деньги int64 сериализуются без потери точности. Нулевые суммы и пустой список операций
с покрытием не превращаются в NO_DATA; partial отличается от отсутствия данных.
DataBounds.data_to остаётся моментом последнего покрытого дня, а не исключительной
границей диапазона.

Адаптер не решает, списывать ли попытку: блокировка постороннего прогноза в полном
GetAnalytics сама по себе не означает неполноту ответа на вопрос о расходах. `present_result`
сопоставляет result_id и путь выбранного блока/плитки с сохранёнными Evidence.LockedPaths.
Выбранный LOCKED показывает серверный текст причины и делает ответ бесплатным.

`present_result` — локальная функция показа, без нового RPC. Она ссылается только на
завершённое чтение предыдущего шага: rows для Aggregate/Find, analytics для выбранного
blocks[i] или blocks[i].data.tiles[j], chart для помесячного Aggregate с подтверждённым
покрытием из Overview той же версии. Числа, даты и чипы строятся из сохранённого ответа
соседа и проверенных аргументов; неизвестный result_id, путь и дополнительные числовые
поля модели отвергаются до вызовов соседей. Показ тоже расходует лимит собственных функций.

Квоты ResultBytes и CollectionItems задаются явно при создании клиента. Слишком
большой или некорректный результат отклоняется целиком; JSON не обрезается, итоговая
сумма не пересчитывается по неполному списку. Это транспортные ограничения, а не
реализация согласованного входного бюджета модели 24k на шаг / 48k на вопрос.

Проверки: unit-тесты преобразований и отрицательных сценариев, реальные gRPC-вызовы
на bufconn через Dial для каждого метода, сервисная идентичность, повтор чтения,
сохранение фильтров и точных сумм, отмена, deadline и отзыв согласия между вызовами.
Платные вызовы модели и работающий общий стенд в этих тестах не используются.
