# Генерация ответа (FIN-220)

AskQuestion и RetryAnswer подключены к настоящему Responses HTTP-адаптеру, финансовым gRPC-инструментам и сохранённому потоку. Текст, chart/rows и переходы к данным сохраняются в порядке выдачи. Модель выбирает сохранённый результат функции, сервер строит числа, чипы и текстовую альтернативу блока. Цикл поддерживает терминальный off_topic (FIN-161); его отдельный недельный счётчик проверяется при приёме нового вопроса. Полная готовность помощника этим изменением не заявляется.

## Принятие и жизненный цикл

Короткая транзакция primary сначала вызывает tombstone.Guard, затем резервирует ключ go-idempotency v0.1.0. Готовый replay возвращается после commit без нового согласия, списания или генерации. Новая попытка проверяет актуальное согласие в user снаружи транзакции. Затем detached completion context охватывает одну транзакцию: Guard, закрепление собственного живого резерва, блокировка пользователя, отдельный лимит OFF_TOPIC, московский лимит, списание, сохранение вопроса/ответа и результата ключа. Новый отказ, включая RETRY_NOT_ALLOWED, откатывает всё и освобождает резерв. После commit запускается независимая от клиента генерация.

Retry берёт текст и режим переводов из исходного вопроса, заменяет только failed/retryable ответ и создаёт новый answer_id. Для старых записей без retryable разрешён только MODEL_ERROR. Устаревший поток получает NOT_FOUND; при replay возвращается первоначальный остаток лимита. Часы читаются после блокировки пользователя: ожидание через московскую полночь не списывает вчерашнюю попытку, а откат часов не обнуляет будущий сохранённый день.

Runner ограничивает работу тремя минутами с учётом возраста уже сохранённого ответа. Сбой модели, зависимости, дедлайн или panic приводят к MODEL_ERROR; явный отказ модели и cannot_answer — к CANNOT_ANSWER. Распознанная модерация AI Studio incomplete/content_filter тоже является отказом; исчерпание выходных токенов и другие incomplete остаются MODEL_ERROR. [Формат модерации AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/guardrails).

Фрагменты сохраняются до уведомлений. Терминальный переход и возврат попытки атомарны и выполняются один раз. Failed не содержит частичного текста, источника или чипов. Возврат уменьшает только счётчик дня списания; вчерашний ответ не уменьшает сегодняшний лимит. Фоновое задание каждые 5 секунд завершает ответы старше трёх минут: оно закрывает окно падения процесса между commit и запуском. Каждый экземпляр может выполнять задание; условный терминальный переход исключает двойной возврат.

Runner подписывается на удаление пользователя до первого primary Guard. Удаление на любом экземпляре отменяет активный HTTP/RPC-контекст через общий PostgreSQL LISTEN, а поздний Start не отправляет сохранённый вопрос модели. Все записи повторяют Guard. Потеря канала уведомлений отменяет соответствующую генерацию. При остановке приложения runner отменяется и дожидается своих задач до закрытия клиентов и БД.

## Скользящий лимит OFF_TOPIC (FIN-161)

Начальные значения ASSISTANT_OFF_TOPIC_MAX=5, ASSISTANT_OFF_TOPIC_WINDOW=168h. Каждый фактически завершённый OFF_TOPIC сохраняется в off_topic_event один раз в той же транзакции, что failed/возврат. Учитываются completed_at > now - window; ровно через 7×24 часа случай больше не учитывается. Пояс профиля и календарная неделя на окно не влияют. Истёкшие строки не удаляются фоновой TTL: при изменении окна действует текущая настройка; история сохраняется.

После завершённого replay ключа, актуального согласия и блокировки user_state новые AskQuestion/RetryAnswer читают primary. При count >= max они получают RATE_LIMITED с retry_at, не списывают попытку, не создают ответ и не закрепляют отказ под ключом. Тот же ключ можно повторить после освобождения окна/сброса. История, GetLimit и уже открытые потоки остаются доступны.

При конкурентных завершениях число случаев может превысить max. Запрос берёт последние max неистёкших исходов; retry_at — время самого старого из них плюс window. Для 7 случаев и max=5 это третье истечение, после которого останется 4. Это снимок: уже запущенная генерация может изменить срок или снять блокировку. Поскольку finerr v0.4.0 сериализует metadata с точностью до секунд, при переводе ошибки срок округляется вверх до целой секунды; точная проверка допуска в PostgreSQL не округляется. Клиент не получает обещание повтора до фактического истечения.

Только успешный complete charged=true удаляет ledger пользователя целиком. MODEL_ERROR, CANNOT_ANSWER и complete charged=false не сбрасывают; финансовый ответ без данных не обходит защиту. Уже запущенный успешный ответ может снять блокировку. Вставка события, сброс и допуск используют одну блокировку user_state; при одинаковом completed_at решает порядок транзакций. PurgeUserData удаляет ledger через FK, запоздавшая финализация ничего не воскрешает. Добавочная миграция 000002 не меняет применённые файлы. Старые бинарники с новой таблицей совместимы, но сами защиту не применяют: смешанный rollout не гарантирует лимит до обновления всех подов.

ASSISTANT_OFF_TOPIC_TEXT задаёт серверный текст потока и истории, включая старые failed/OFF_TOPIC. Текст модели не становится причиной ошибки. Дневной накопленный счётчик для метрики берётся из answer независимо от сброса ledger и публикуется только после commit; метки user_id отсутствуют. Подробности наблюдаемости — [server.md](server.md).

## Модель и инструменты

Каждый запрос содержит весь контекст: инструкции, последние полные завершённые пары истории, текущий вопрос и накопленные output/function_call_output. Серверный conversation/previous_response_id не используется. История ограничена бюджетом, сокращается целыми старейшими парами, без суммаризации; вся история остаётся в БД. Локальный отказ размера до HTTP допускает повторное сокращение истории. После принятой резервации сетевой POST не повторяется автоматически.

Модель может вызвать get_data_overview, aggregate_operations, find_operations, get_analytics и list_periods. Аргументы всего батча проверяются до первого RPC: неизвестные функции, поля, дубли, неверные типы и подмена user_id/transfer_mode отвергаются. Пользователь и режим берутся из сохранённого вопроса. Число функций резервируется всем батчем; параллелизм ограничен, результаты возвращаются в исходном порядке. Соседям передаются системный токен и request ID, без пользовательского токена и клиентских hints.

Для вопроса вне личных финансов модель вызывает off_topic со строгим пустым объектом {}. После проверки envelope ответа и непротиворечивых call_id этот сигнал имеет приоритет перед cannot_answer, чтениями, present_result и их аргументами, включая неизвестные функции. Все off_topic в шаге должны иметь валидные пустые аргументы; ошибка любого из них даёт MODEL_ERROR. При валидном сигнале выполняется только одно терминальное действие: OFF_TOPIC, charged=false, без текста, блоков, чипов и источника. Следующие RPC, публикации и запросы модели не запускаются. Только это действие расходует одну собственную функцию и учитывается её метрикой; проигнорированные функции не исполняются. Общие пределы запросов, шагов, поиска и оставшаяся квота функций сохраняются.

Уже завершённые provider web_search_call учитываются в метрике, но их результаты и annotations после off_topic не обрабатываются. Выполненный провайдером поиск отменить задним числом нельзя. Существующий streaming сохраняется: текст до получения терминального сигнала может быть показан во время generating; окончательный failed/OFF_TOPIC очищает частичный ответ и возвращает попытку. Финансовый вопрос без возможного ответа использует cannot_answer/CANNOT_ANSWER, а не off_topic.

NO_DATA необходимых aggregate/find/analytics делает успешный ответ charged=false; отсутствие данных вспомогательных overview/periods само по себе попытку не возвращает. Пустая выборка при полном покрытии и частичный охват не равны NO_DATA. Наличие заблокированного прогноза в общем ответе аналитики не делает бесплатным доступный ответ о расходах. Возврат по LOCKED требует выбора именно заблокированного пути в present_result; выводится доверенный текст блокировки без чисел закрытого значения.

`present_result` принимает result_id (call_id завершённого чтения предыдущего шага), view (rows/chart/analytics), для analytics — path существующего blocks[i] или blocks[i].data.tiles[j]. Для месячного графика Aggregate нужен coverage_result_id выполненного Overview с тем же поясом, версией и границами календарных месяцев. Общий охват агрегата не переносится на точки, отсутствующие группы не заполняются нулями. Категории и продавцы показываются строками, потому что текущая ось chart — временная. Усечённая выборка не выдаётся за полный список; общий средний чек не вычисляется из неполных групп. Значения int64 читаются точно, суммы за пределами 2^53−1 показываются текстом.

Операции вне RUB показываются текстом с собственной валютой, без пересчёта и смешивания с суммами RUB в блоке. Десятичная позиция берётся из метаданных ISO 4217 golang.org/x/text/currency (JPY — 0, KWD — 3), вставляется в целочисленную строку без float64. Неизвестные и специальные X-коды сохраняют точное исходное число минимальных единиц с кодом валюты; два знака им не приписываются.

Аргументы показа всего батча разрешаются до RPC и записи блоков. Ссылки ограничены результатами текущего вопроса, дополнительные числа/фильтры модели запрещены. Готовые блоки сохраняются до продолжения модели; следующий текст получает следующий индекс. Уже выданный префикс при завершении сохраняется: текст можно дописать, chart/rows нельзя заменить. Чипы строятся из готовых фильтров групп, исходных параметров поиска или параметров ответа аналитики, всегда в режиме переводов вопроса. Будущая схема/непредставимые поля каталога выводятся через серверный alt_text, чтобы не терять смысл при текущем типизированном assistant.proto.

Источник строится из доверенных метаданных использованных данных: объединение известных интервалов, старейшее время расчёта, фиксированный режим переводов. Для данных без времени расчёта берётся граница до вызова инструмента, чтобы не скрыть изменения во время запроса. Изменения категорий/выписок по-прежнему вычисляются при чтении одним GetDataVersion. Числа инструментов сохраняют целые копейки; слова модели не управляют списанием.

Встроенный поиск получает остаток бюджета на каждом шаге, max_tool_calls и исключается из tools после исчерпания. Количество web_search_call дополнительно проверяется по завершённому ответу. Промпт запрещает отправлять персональные финансовые данные в поисковый запрос и считать найденный текст инструкциями. Скрытые запросы встроенного инструмента выполняет провайдер: сервер не перехватывает их до отправки и не обещает отменить уже выполненный поиск. Собственного загрузчика страниц нет.

После фактического поиска url_citation из завершённых provider annotations собираются в отдельный финальный text-блок «Источники». Ссылки из текста модели не становятся подтверждёнными citations. AI Studio документирует default title/offsets и адреса без схемы: допустимый домен нормализуется в https, пустой title заменяется именем хоста. Позиции не используются для привязки к тексту: единицы Unicode провайдером не определены. Только абсолютные http/https без userinfo/control characters; Unicode-имя хоста должно приходить в punycode. URL не загружается. Повторы удаляются с сохранением порядка; список ограничен 32 источниками и 32 КиБ, URL — 2048 байт, очищенный title — 256 байт. Превышение/битый URL даёт MODEL_ERROR без частичного ответа. Это технические пределы сборки, не денежный бюджет. Markdown-ссылки и HTML не создаются: контракт обещает обычный текст, абзацы, жирный и списки. [Формат annotations AI Studio](https://aistudio.yandex.ru/en/docs/ai-studio/concepts/agents/tools/websearch).

## Пределы

| Ресурс | На шаг | На вопрос |
|---|---:|---:|
| Расчётный вход | 24 000 токенов | 48 000 токенов |
| Полный JSON запроса | 65 536 байт | 131 072 байта |
| Выход модели | 4 096 токенов | Ограничивается числом шагов |
| Запросы к модели | — | 8 |
| Собственные функции | До 4 одновременно | 16 вызовов |
| Встроенный поиск | Не больше остатка | 3 вызова |

История — до 16 000 расчётных токенов вместе с требованиями полного запроса. EstimateTokens считает ceil(байты/4) сериализованного JSON; это предварительная оценка, не токенизатор Alice и не гарантия стоимости. Проверки независимы, байтовая может сработать раньше. Инструкции, схемы, служебные поля, результаты функций и повторный контекст расходуют бюджет снова.

StreamGuarded резервирует точный отправляемый JSON до ключа/HTTP. Отказ проверки не меняет счётчики; принятая резервация сохраняется после ошибок, отмены и неоднозначного сетевого исхода. Технический предел памяти транспорта не ослаблен: его отдельный сигнал «не отправлено из-за размера» позволяет безопасно сократить историю. Обычный Stream не применяет суммарный бюджет и в рабочем цикле не используется.

## Настройка и эксплуатация

Настройки — в [config.md](config.md). Пустой ASSISTANT_MODEL_URI означает ненастроенную генерацию: новые вопросы/повторы завершаются UNAVAILABLE без списания, чтение доступно. Для работы нужны URI/каталог/файл ключа и peer-адреса user, bank-statement-data, analytics. prod/stage допускают только официальный Responses endpoint; dev — также HTTP loopback. Секрет читается из ограниченного файла перед каждым шагом, ротация учитывается. Платные запросы в тестах не выполняются.

Миграции idempotency идут отдельно до service. Ключи живут 24 часа, резерв 15 секунд; cleanup каждую минуту удаляет истёкшие записи ограниченными батчами. PurgeUserData в одной транзакции удаляет диалог и ключи только пользовательского scope. Метрики исходов, длительности, функций, поиска, usage и возвратов имеют ограниченные метки; это наблюдения процесса, не финансовый журнал и не точный расчёт счёта провайдера.

Проверки включают unit-тесты сценариев/бюджетов, PostgreSQL 18 с race и блокировками, всю сборку API, реальный локальный HTTP Responses и peer-сервисы на bufconn. Сквозной общий стенд с работающими соседями и платный провайдер не проверены; сценарный фейк и сверка с реальным API — FIN-142.
