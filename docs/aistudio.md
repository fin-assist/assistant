# HTTP-адаптер Yandex AI Studio (FIN-220)

`internal/adapter/aistudio` реализует один потоковый POST Responses API. Это подготовительный этап: адаптер ещё не включён в `internal/app/wire.go`; AskQuestion и RetryAnswer остаются UNIMPLEMENTED. Согласие, списание/возврат попытки, сохранение, цикл инструментов и общий трёхминутный срок генерации относятся к следующему этапу. Новый бинарь/сценарный сервер FIN-142 здесь не создаётся.

## Протокол и владение ресурсами

- Один `Client` переиспользует HTTP transport; владелец сначала отменяет/завершает активные вызовы, затем вызывает Close. Каждый Stream требует deadline в контексте. Транспорт не делает автоматических повторов POST при 429, 5xx, обрыве или частичном результате: повтор мог бы создать ещё одну платную генерацию.
- На каждом шаге: Authorization Bearer, OpenAI-Project, `x-data-logging-enabled: false`, `stream: true`, `store: false`, `truncation: disabled`. Полный вход передаёт вызывающий. Conversation/previous_response_id, structured output и размещённые у провайдера цепочки контекста не используются. Нельзя считать один заголовок отключения логирования настройкой хранения истории Responses — поэтому store задаётся отдельно.
- Функции и их JSON Schema передаются в tools. `max_tool_calls` ограничивает встроенные инструменты одного HTTP-запроса; число наших функций и суммарный поиск за весь ответ должен отдельно считать будущий цикл. Адаптер не выполняет функций и не загружает страницы.
- SSE проверяется по жизненному циклу: создание ответа, добавление элемента/части, фрагменты, завершение части/элемента и завершение ответа. ID, индексы, текст и аргументы сверяются с итоговым output; неизвестные критичные события, неоднозначные JSON-поля, отрицательный usage, неполный/ошибочный ответ и обрыв до завершения отвергаются. Отказ модели выделен ErrRefused, чтобы будущий сценарий мог отличить CANNOT_ANSWER от MODEL_ERROR.
- Текст передаётся callback по мере прихода. Успехом считается только Result после проверенного завершения: вызывающий обязан отбросить частичный ответ при ошибке. Ошибка callback и отмена контекста сохраняются.
- Итоговые output items сохраняются в raw JSON: сообщения с annotations/url_citation, вызовы функций, reasoning и web_search_call. Вызывающий передаёт их в следующий шаг вместе с function_call_output и проверяет имена/аргументы функций до выполнения. Неизвестные поля известных items сохраняются; неизвестный тип item отклоняется. Денежные значения и счётчики не проходят через float64. Usage содержит input/output/total/tool_tokens; реальный биллинг и формат расширений провайдера ещё предстоит сверить в FIN-142.

## Границы

Положительные Limits передаются явно: размер запроса, всего ответа, одного SSE-события, аргументов одной функции и число output items. Значения по умолчанию и параметры генерации здесь не фиксируются: итоговая политика токенов/стоимости ещё обсуждается с владельцем. Ограничения байтов не заменяют токеновый бюджет.

Ответ должен быть text/event-stream без сжатия. Ограничены заголовки и ожидание TCP/TLS/HTTP headers; чтение body ограничивает deadline вызывающего. Перенаправления запрещены, переменные proxy не используются. Body закрывается на каждом исходе.

prod/stage принимают только `https://ai.api.cloud.yandex.net/v1/responses`, без credentials/query/fragment/нестандартного порта. dev дополнительно принимает HTTP loopback по тому же пути, для локальных HTTP-тестов и будущего FIN-142. Модель задаётся явно URI Alice AI LLM/Flash из того же каталога. Это правила конструктора адаптера, новых переменных окружения работающего сервиса пока нет.

Ключ поступает через KeySource на каждый запрос. FileKey читает ограниченный обычный файл и видит атомарную замену без перезапуска. В ошибках нет ключа, пути файла, URL запроса, содержимого диалога или тела ответа провайдера. Реальные ключи в репозиторий и чат не передаются.

## Проверки и пределы доказательств

Юнит-тесты проверяют JSON/SSE, порядок событий и параллельные фрагментированные функции, Unicode, отказы/неполное завершение, дубли и несовпадения, лимиты и ротацию ключа. HTTP-тесты вызывают настоящий локальный сервер: заголовки на каждом шаге, ручной контекст с результатом функции, запрет redirect и повторов, размеры, тип ответа, cancellation/deadline и закрытие body.

Все ранее реализованные RPC проверяются прежними API-тестами через настоящую сборку с PostgreSQL 18. Этот PR не добавляет gRPC-методов или публичных полей. Платные запросы к AI Studio не выполнялись; успешные тесты по документированному протоколу не подтверждают доступность модели/квот реального каталога. Сверка с настоящим провайдером и сценарный фейк — FIN-142.
