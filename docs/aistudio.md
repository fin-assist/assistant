# HTTP-адаптер Yandex AI Studio (FIN-220)

`internal/adapter/aistudio` реализует один потоковый POST Responses API и подключён в `internal/app/wire.go` через GenerationModel. AskQuestion/RetryAnswer запускают цикл с инструментами, бюджетом, серверным построением блоков и сохранением; его поведение и оставшиеся этапы — в [generation.md](generation.md). Raw annotations передаются в collector цитат после подтверждённого завершения и фактического поиска; HTTP-адаптер сам не строит клиентские блоки. Сценарный сервер FIN-142 здесь не создаётся.

## Протокол и владение ресурсами

- Один `Client` переиспользует HTTP transport; владелец сначала отменяет/завершает активные вызовы, затем вызывает Close. Каждый Stream требует deadline в контексте. Транспорт не делает автоматических повторов POST при 429, 5xx, обрыве или частичном результате: повтор мог бы создать ещё одну платную генерацию.
- На каждом шаге: Authorization Bearer, OpenAI-Project, `x-data-logging-enabled: false`, `stream: true`, `store: false`, `truncation: disabled`. Полный вход передаёт вызывающий. Conversation/previous_response_id, structured output и размещённые у провайдера цепочки контекста не используются. Нельзя считать один заголовок отключения логирования настройкой хранения истории Responses — поэтому store задаётся отдельно.
- Функции и их JSON Schema передаются в tools. `max_tool_calls` ограничивает встроенные инструменты одного HTTP-запроса; число наших функций и суммарный поиск считает internal/generation. Сам адаптер не выполняет функций и не загружает страницы.
- SSE проверяется по жизненному циклу: создание ответа, добавление элемента/части, фрагменты, завершение части/элемента и завершение ответа. ID, индексы, текст и аргументы сверяются с итоговым output; неизвестные критичные события, неоднозначные JSON-поля, отрицательный usage, неполный/ошибочный ответ и обрыв до завершения отвергаются. Отказ модели выделен ErrRefused и преобразуется в CANNOT_ANSWER, остальные сбои — в MODEL_ERROR. Распознанный incomplete/content_filter относится к отказам, исчерпание токенов — к сбоям.
- Текст передаётся callback по мере прихода. Успехом считается только Result после проверенного завершения: вызывающий обязан отбросить частичный ответ при ошибке. Ошибка callback и отмена контекста сохраняются.
- Итоговые output items сохраняются в raw JSON: сообщения с annotations/url_citation, вызовы функций, reasoning и web_search_call. Вызывающий передаёт их в следующий шаг вместе с function_call_output и проверяет имена/аргументы функций до выполнения. Неизвестные поля известных items сохраняются; неизвестный тип item отклоняется. Денежные значения и счётчики не проходят через float64. Usage содержит input/output/total/tool_tokens; реальный биллинг и формат расширений провайдера ещё предстоит сверить в FIN-142.

## Границы

Положительные Limits передаются явно: размер запроса, всего ответа, одного SSE-события, аргументов одной функции и число output items. Согласованная политика и настройки описаны в [generation.md](generation.md) и [config.md](config.md). Вход ограничивается одновременно расчётными 24 000 токенов на шаг / 48 000 на вопрос и строгими 65 536 / 131 072 байтами полного отправленного JSON. Инструкции, схемы, вопрос, история, служебные поля и результаты функций входят в бюджет; повтор контекста расходует его снова. Оценка `ceil(bytes/4)` не является токенизатором Alice или пределом стоимости. Максимум истории — 16 000 расчётных токенов; вместе с обязательным входом она должна проходить обе проверки и может оказаться короче.

`StreamGuarded` после единственной сериализации передаёт точные отправляемые байты проверке бюджета. Проверка выполняется до чтения ключа и HTTP; её ошибка возвращается без изменений. Общий `generation.Budget` должен жить весь вопрос, включая следующие шаги. Прежний `Stream` остаётся совместимым транспортным методом без суммарного бюджета; рабочий цикл обязан использовать `StreamGuarded`. Резервирование не возвращается при ошибке провайдера или неоднозначном сетевом исходе. Общий бюджет подключён к публичному циклу и проверен локальными HTTP- и API-тестами. ErrRequestTooLarge означает безопасный отказ до ключа/HTTP и позволяет сократить историю, сохраняя технический предел транспорта. Скрытое потребление встроенного поиска эти проверки не ограничивают.

Ответ должен быть text/event-stream без сжатия. Ограничены заголовки и ожидание TCP/TLS/HTTP headers; чтение body ограничивает deadline вызывающего. Перенаправления запрещены, переменные proxy не используются. Body закрывается на каждом исходе.

prod/stage принимают только `https://ai.api.cloud.yandex.net/v1/responses`, без credentials/query/fragment/нестандартного порта. dev дополнительно принимает HTTP loopback по тому же пути, для локальных HTTP-тестов и будущего FIN-142. Модель задаётся явно URI Alice AI LLM/Flash из того же каталога. Конфигурация сервиса проверяет те же ограничения.

Ключ поступает через KeySource на каждый запрос. FileKey читает ограниченный обычный файл и видит атомарную замену без перезапуска, если путь указывает на сам файл. На стенде (`LoadCredential=`, FIN-349) процесс читает копию, сделанную systemd при старте: замена ключа в `/etc/finassist/assistant/` применяется только после перезапуска, поэтому там — статический API-ключ, не IAM-токен. В ошибках нет ключа, пути файла, URL запроса, содержимого диалога или тела ответа провайдера. Реальные ключи в репозиторий и чат не передаются.

## Проверки и пределы доказательств

Юнит-тесты проверяют JSON/SSE, порядок событий и параллельные фрагментированные функции, Unicode, отказы/неполное завершение, дубли и несовпадения, лимиты и ротацию ключа. HTTP-тесты вызывают настоящий локальный сервер: заголовки на каждом шаге, ручной контекст с результатом функции, запрет redirect и повторов, размеры, тип ответа, cancellation/deadline и закрытие body.

API-тесты проверяют настоящую сборку с PostgreSQL 18, Ask/Retry, HTTP-моделью и соседями на bufconn. Публичные поля не менялись. Платные запросы к AI Studio не выполнялись; успешные тесты по документированному протоколу не подтверждают доступность модели/квот реального каталога. Сверка с настоящим провайдером и сценарный фейк — FIN-142.

Источники: [Responses API](https://aistudio.yandex.ru/en/docs/ai-studio/api/Responses/createResponse), [функции и ручная передача output](https://aistudio.yandex.ru/en/docs/ai-studio/operations/agents/create-function-text-agent), [отключение логирования](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging), [политика хранения](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage). Проверены 23.10.2026.

FIN-256 дополнительно проверяет границу настоящего HTTP/SSE transport → `GenerationModel`: порядок событий, идентификаторы response/item, function arguments, точное сравнение final raw JSON (включая большие целые), неоднозначный framing, usage и отказ модерации. При ошибке terminal result, usage и функции отсутствуют; уже выданные допустимые текстовые фрагменты остаются предварительными. Ошибки не содержат приватный payload; на каждый сценарий приходится ровно один бюджетный reserve и один POST без автоматического повтора. Это локальные component integration-тесты существующего адаптера; сценарная платформа FIN-142 не реализуется.
